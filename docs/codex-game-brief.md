# Codex Game Brief

This is the short version I can rely on during Claude handoffs.

## What the app is today

World1 is currently a **combat demo** for a larger 1v1 roguelite battler.
The playable loop right now is:

1. Open `PrepScene`
2. Use one of the out-of-combat tabs:
   `Loadout` to place cards, `Bag` to review the collection/current build,
   `Wiki` to browse all cards and enemy boards
3. Pick an enemy and a seed
4. Start `BattleScene`
5. Watch a deterministic combat playback generated by the engine

The full run layer is not built yet. There is no map, shop, forge, draft,
meta-progression, or menu flow in the app today.

## Ownership split

- Claude owns `src/engine/`, `src/data/`, `src/run/`, balance, tests, and game rules.
- Codex owns `src/game/` and shared UI docs.
- Only `src/game/` may import `phaser`.
- The battle UI must never recompute combat. If a needed value is missing, request
  it from Claude through `docs/codex-handoff.md`.

## Core gameplay rules I need to understand

- Combat is deterministic: `simulate(config, seed)` returns `{ result, events, finalState }`.
- Each turn compares `bank + speed - queued weight`.
- Higher score performs. Tie goes to the player. The loser banks speed.
- A size-`N` card spans `N` turns, so larger cards stay busy longer.
- Damage has three properties: `physical`, `magical`, and `true`.
- Typed shields stack, carry over, and cap at max HP.
- Matchup advantages come from element and weapon relationships.
- Status and rider effects are surfaced through the combat event log.
- Sudden death and fatigue exist as explicit event types in playback.

## Prep scene behavior

- [`src/game/scenes/PrepScene.ts`](/C:/Users/wenwa/source/repos/wwang109/world1/src/game/scenes/PrepScene.ts) is the out-of-combat hub. It contains:
  `Loadout` for drag/drop board building,
  `Bag` for current-build plus collection browsing,
  `Wiki` for all cards plus an enemy dossier.
- Board placement rules do not live in the scene. The scene calls `canPlace()` and `clampSlot()` from `src/run/loadout.ts`.
- Dragging a board card off the board removes it.
- Enemy preview shows stats, affinities, and a miniature board layout.
- Clicking or hovering any visible skill routes through the shared detail panel.
- Seed changes are UI-only and currently use `Math.random()` in the scene, which is acceptable because simulation determinism comes from the chosen seed.

## Battle scene behavior

- [`src/game/scenes/BattleScene.ts`](/C:/Users/wenwa/source/repos/wwang109/world1/src/game/scenes/BattleScene.ts) calls `simulate()` once at scene creation.
- The scene then walks the returned `events` array as a playback timeline inside a three-lane layout: hero cards left, plays/comparison center, enemy cards right.
- UI state is local view state only: HP bars, shield bar width, status text, log lines, banners, and card highlights.
- Event timing comes from the local `DELAYS` map.
- Controls currently support playback speed, skip, replay, back to prep, and new seed.
- Skills are clickable during combat and update the center detail panel.
- Floating numbers and cast highlights are presentation only and must stay non-authoritative.

## Fast answers for common handoffs

- To add or change visuals, work in `src/game/`.
- To jump directly to a target screen in dev, use URL params:
  `?view=loadout`, `?view=bag`, `?view=wiki`, or `?scene=battle`.
  Useful extras: `?enemy=wolf_king`, `?seed=42`, `?board=empty`.
- To add a new scene, register it in `src/main.ts`.
- To change card visuals, start with `CardView` and `theme.ts`.
- To explain why something appears in battle, trace the matching combat event kind first.
- To show a value the scene cannot derive safely, request a new event field from Claude.
- To scaffold future run screens, mock a small view-model shape and record the assumption in `docs/codex-handoff.md`.

## Current design state

- The existing UI is functional but still a prototype.
- The main design target is readability of combat math, matchup context, shields,
  statuses, and cast flow.
- The current shared backlog starts with visual elevation of Prep and Battle
  before expanding into the missing run-layer screens.
